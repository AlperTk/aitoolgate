# mcp-manager — Tool-call metrics (duration + tokens)

> Post-MVP addition: per-tool-call execution duration (ms) + token consumption, surfaced in `/api/stats` + dashboard. Rationale → `decisions.md`; traps → `pitfalls.md`; exact shapes → `api-reference.md`. Test baseline moved 132 → **165 tests / 0 fail**.

## What it does
For every LLM-issued tool call, record:
- **Duration (ms):** real tool-execution window — from when the call is ISSUED (response N carries `tool_calls[].id`) until its result ARRIVES (request N+1 carries the matching `role:'tool'` / Anthropic `tool_result`). Paired by `(sessionKey, toolCallId)` across successive requests of the same session.
- **Tokens:** the upstream `usage` of the turn that produced the call, normalized to a consistent `{ input?, output?, total? }` shape (`total = input+output` when both present, else the single value, else omitted), attached to each `tool.call`. Every emitted `tool.call` carries a STABLE UNIQUE `id` (upstream tool-call id verbatim, else deterministic `${sessionKey}#${at}#${index}`, `~N` disambiguation on same-turn collision) so batched parallel calls never share an id. Raw payload size is also exposed as `chars` on `tool.result` (no tokenizer — zero external deps).
Surfaced as per-tool aggregates + global totals via `Collector.summary()` → `GET /api/stats`, plus dashboard tiles/columns.

## Key files
- `src/telemetry/toolMetrics.ts` — bounded cross-request pairing tracker. `createToolMetricsTracker({maxPending?=1000, ttlMs?=300000, now?=Date.now})` → `{ recordIssued(sessionKey, {id,at,name?}[]); resolveResults(sessionKey, {toolCallId?,at,chars?}[]): {toolCallId,durationMs,chars?,toolName?}[]; pendingCount(); reset() }`. In-memory only, NO timers; TTL+capacity enforced lazily with an injectable clock; primary key `${sessionKey}\u0000${id}`; `resolveResults` matches the same-session bucket first, then falls back to matching BY `toolCallId` across sessions (most-recent compatible entry) so a diverging/empty `x-session-id` can't strand a call; returns only matched ids, clamps duration to ≥0, and carries the issued tool `name` as `toolName`.
- `src/proxy/context.ts` — CENTRALIZED emission. `summarizeResponse` returns `{toolCalls, content, usage?}`; `emitResponseTelemetry` runs UNCONDITIONALLY at response-out on EVERY path, attaching a STABLE UNIQUE `id` (always non-empty; `stableToolCallId`, fed to BOTH the event and `recordIssued`) + the `{input,output,total}` turn `tokens` to each `tool.call`, and calling `tracker.recordIssued`. Request-phase detects incoming tool results (both protocols) → `tracker.resolveResults` → emits a REAL per-result `tool.result` with `toolCallId`/`durationMs`/`chars`. The old SYNTHETIC single per-response `tool.result` was removed.
- `src/policy/policyStage.ts` — emits ONLY `policy.intervention` events; its own `tool.call` emission was REMOVED (prevents double-count and ensures `recordIssued` is never skipped). Do NOT re-add tool-call emission here.
- `src/telemetry/collector.ts` — aggregates per-tool `{avg,max,total}DurationMs` + global `totalDurationMs/avgDurationMs/totalInputTokens/totalOutputTokens/totalTokens`. Token sums DEDUPED per `(sessionKey, at)` turn so a multi-call turn counts once (bounded set, `maxTokenTurns?=10000`). New summary/topTools fields are OPTIONAL (omitted until data exists). **Aggregate exclusion:** `createCollector({excludedTools?=['task']})` drops matching-name events from ALL aggregates (call-side: totalCalls / top-tools / token sums; result-side: totalResults + total & avg duration), while raw retention (`getRecentEvents`) and `perSession` stay RAW so the live stream still shows them — see `aggregate-exclusions.ts`.
- `src/api/ws.ts` — FIXED latent bug: `encodeFrame` set the RFC6455 MASK bit on unmasked server→client frames for lengths >125 bytes (wrote `0xfe`/`0xff`); larger real `tool.call` payloads tripped it and hung the WS e2e. Now writes `0x7e`/`0x7f`.
- `src/server/index.ts` + `src/proxy/index.ts` — ONE shared tracker instantiated in `createProxyHandler`, exposed non-enumerable on `.telemetry.tracker` and `McmServerHandle.tracker`. Same-protocol **streaming** paths feed the tracker via `src/telemetry/stream-extract.ts` (now protocol-aware: parses OpenAI-shaped frames (OpenAI same-protocol streamed requests inject `stream_options.include_usage=true` via `openai.ts` so a trailing usage chunk is emitted) AND native-Anthropic `content_block_*` tool_use frames, normalizes merged split usage to `{input,output,total}`, and attaches that `tokens` + a stable unique `id` to each emitted `tool.call` with one shared turn-level `at`; `openai.ts`/`anthropic.ts` `streamSameProtocol` call `resolveAndEmitToolResults` in the request phase so pending issued calls resolve even when the follow-up is itself streamed).
- `src/telemetry/aggregate-exclusions.ts` — NEW shared constant `DEFAULT_AGGREGATE_EXCLUDED_TOOLS = ['task']` + `isAggregateExcluded(toolName, excludedTools?)` (case-insensitive). The `task` tool spawns a fresh sub-agent session whose whole-session duration/token mass is written back into its single parent result, so it is filtered out of all aggregates; inner sub-agent calls keep counting. See `decisions.md`.
- `dashboard/*` — top-tools table gained Avg(ms)/Max(ms) columns; new tiles: total/input/output tokens + total/avg duration (`fmtOpt` renders `—` when a field is absent early-run). Per-call **duration + tokens now also surface in the LIVE tool-call list** (one row per logical call, paired call↔result by id with a sessionKey fallback; `—` until the result arrives) — see `dashboard-ui.md`.

## Business rules / assumptions
- **Sequential-single-client** pairing: duration relies on per-session request ordering (consistent with the existing "last request" session-key design); `x-session-id` is header-only and resolution now ALSO falls back to matching BY `toolCallId` across sessions (`toolMetrics.resolveResults`) so a diverging/empty header can't permanently strand a call. Concurrent multi-client traffic sharing one session key may still mis-pair issue/result.
- Tokens = real upstream usage aggregated at TURN level (deduped), NOT fabricated per-tool splits; each `tool.call` carries the turn's usage as `{input?, output?, total?}` (one row's large "Total" = the WHOLE-turn in+out, dominated by resent history, NOT a single tool's cost). Every `tool.call` carries a stable unique `id`. `chars` is raw payload size (best-effort, not token-accurate — no dependency budget for a tokenizer); it surfaces as the dashboard's always-available Size column.
- A call whose result never arrives (blocked/loop/stopped client) contributes to `totalCalls`/top-tools but yields NO `tool.result`/duration until its result is seen (or the pending entry ages out via TTL/cap).
- **Aggregates exclude nested-wrapper tools:** events whose `toolName` matches `excludedTools` (default `['task']`, case-insensitive) are omitted from ALL aggregate stats (totals + averages + top-tools) because the `task` wrapper carries an entire sub-agent session's cost; raw event retention and `perSession` are unaffected, so the live stream still shows each such event. Its inner sub-agent tool calls (own names, own session) still count.
- **Streaming metrics work** for both OpenAI-shaped AND native-Anthropic streamed responses (extractor is protocol-aware — see Key files): a streamed turn's upstream usage is attached to its `tool.call`(s) and its pending calls resolve on the next same-session request carrying the result(s), even if that request/response is itself streamed. Cross-protocol streaming stays buffered/unaffected.
