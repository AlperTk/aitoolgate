# mcp-manager — Dashboard UI (dependency-free vanilla-JS SPA, modular ES modules)

> Real-time local dashboard: live tool-call stream + counts/top tools + intervention log, with policy-rule authoring on its OWN page, plus a global-controls toolbar. Built as **vanilla JS** (NO React/Vite/Tailwind/shadcn, NO `ws` package), served same-origin at `/` by the same process, **not compiled**. Design → `architecture.md`; exact endpoints/types → `api-reference.md`; build/serve rules → `conventions.md`. **No DOM/browser tests exist** — verify changes via `node --check` on each module + `npm test` (~167 green) + structural/DOM-id checks + a runtime HTTP smoke + a manual browser pass.

## Key files
- `dashboard/index.html` — static shell; two page views keyed by id (`#view-dashboard`, `#view-rules`); panels keyed by id (`#stream-panel`, `#stats-panel`, `#interventions-panel`, `#rules-panel`). Loads `<script type="module" src="app.js">`.
- `dashboard/app.js` — **thin ES-module entrypoint only** (imports + `init()`). Does NOT contain feature logic. Runs `init()` guarded by `document.readyState === 'loading' ? DOMContentLoaded : init()`.
- `dashboard/js/*.mjs` — the real logic, split into single-responsibility ES modules (see Module map below). Imports are explicit relative ESM (`import … from './dom.mjs'`); graph is **acyclic**; no duplicated symbol definitions.
- `dashboard/styles.css` — hand-written dark-theme styles; layout driven by ID/`grid-column`.
All of these are served **raw (not compiled)** by `src/server/index.ts`. Do **not** add dependencies or compile the dashboard. See the "Dashboard serving" section of `conventions.md` for how assets are resolved/served (a general safe-asset resolver now serves any `dashboard/js/*.mjs` without further server edits).

## Module map (`dashboard/js/`) — single responsibility per file
- `constants.mjs` — tunables/config: `MAX_LIST_ITEMS`, `STATS_POLL_MS`, `WS_RECONNECT_MS`, `EVENTS_POLL_MS`, `WS_KEEPALIVE_MS`, `WS_DEAD_AFTER_MS`, `MAX_SEEN_EVENTS`, `NO_DATA_TIP`, `TIME_PRESETS`. (Leaf.)
- `dom.mjs` — pure DOM/format + notice helpers: `$` (by-id), `el`, `esc`, `fmtTime`, `isPlainObject`, `errMsg`, `shortSession`, `fmtOpt`, `setStatValue`, `showNotice`, `clearNotice`, `showFormError`. (Imports constants.)
- `state.mjs` — **single exported mutable `state` object** = the shared app context (replaces the old IIFE closure): `ws`, `reconnectTimer`, `localCounts`, `editingId`, `curMatcherType`, `curActionType`, `eventsPollTimer`, `keepaliveTimer`, `wsLastInboundAt`, `seenEventKeys` (Set), `callRows` (Map), `orphanResultEntries` ([]), `interventionsBySession` (Map), `timeRange` ({mode:'all',…}), `interventionRowData` (Map). Modules import this ONE object and read/mutate it. (Leaf.)
- `rule-schema.mjs` — `MATCHER_FIELDS`, `ACTION_FIELDS` field schemas. (Leaf.)
- `time.mjs` — pure time-range helpers: `inTimeRange(at)`, `parseLocalDatetime(value)`, `stamp(at)`. (Leaf; imported by both live-view and controls so neither must import the other.)
- `stats.mjs` — `statNumCell`, `renderTopTools`, `refreshStats` (GET `/api/stats`), and `initTopToolsSort()` (see Counts & Top Tools). Sort state is **module-local** (does not touch `state.mjs`).
- `live-view.mjs` — stream rows, call↔result pairing, orphan rows, drill-down detail, filters, intervention-log rows, live counters, bounded history: `prependTrim`, `appendTokenAndSizeCells`, `setNumCellText`, `createCallRow`, `updateCallRowWithResult`, `createOrphanResultRow`, `findCallForResult`, `matchAndRenderResult`, `storeInterventionForDrillDown`, `bindRowClick`, `renderRowDetail`, `trimCallData`, `applyFilters`, `bindFilterEvents`, `addInterventionRow`, `updateLiveCounters`. (Imports dom/state/constants/time.)
- `ingest.mjs` — deduped event entry: `eventKey`, `ingestEvent`, `handleWsMessage`. WS `onmessage` → `handleWsMessage` (which sets `state.wsLastInboundAt` + renders); the **poll path funnels through `ingestEvent`, NOT `handleWsMessage`**, so polling activity never refreshes WS liveness. (Imports live-view.)
- `transport.mjs` — WS lifecycle + fallback polling + keepalive: `setConnected`, `wsIsOpen`, `syncConnectivity`, `isValidSameOriginWsUrl`, `connectWS`, `scheduleReconnect`, `pollEvents` (GET `/api/events` → `ingestEvent`), `startEventsPolling`/`stopEventsPolling`, `startKeepalive`/`stopKeepalive`. Keepalive starts inside `connectWS`'s `ws.onopen`; dead detection compares `Date.now() - wsLastInboundAt > WS_DEAD_AFTER_MS` and is independent of polling. (Imports ingest.)
- `rules.mjs` — policy-rule list + authoring form in ONE module (they call each other both ways; kept together to stay acyclic): `renderRuleRow`, `renderRules`, `refreshRules` (GET), `toggleEnabled` (PATCH), `deleteRule` (DELETE), `makeField`, `setFieldControlValue`, `renderMatcherFields`, `renderActionFields`, `readField`, `readSection`, `clientValidate`, `collectSpec`, `loadSpecIntoForm`, `resetForm`, `updateFormMode`, `saveRule` (POST/PATCH), `submitRule`, `bindFormEvents`. List↔form round-trips use `state.editingId` / `state.curMatcherType` / `state.curActionType`. (Imports dom/state/rule-schema.)
- `controls.mjs` — global-controls toolbar: `csvCell`, `downloadFile`, `callRecordFromRs`, `interventionRecord`, `getVisibleCalls`, `getVisibleInterventions`, `clearOnScreenHistory`, `buildCallsCsv`, `buildInterventionsCsv`, `exportJson`, `exportCsv`, `onTimeRangeChange`, `applyCustomTimeRange`, `bindControlEvents`. Time helpers come from `time.mjs`; re-renders via `live-view.applyFilters`. (Imports dom/state/constants/live-view/time.)
- `views.mjs` — client-side page routing: `initViews()`. Hash-based via native `hashchange`: hash containing "rules" → policy-rules page, else dashboard. Toggles `.is-active` on the views + header nav links; calls `refreshRules()` when the rules page activates. Does NOT stop/start WS/polling (data keeps flowing in the background). (Imports dom/rules.)

### `app.js` `init()` wiring order
`bindFormEvents`, `bindFilterEvents`, `bindControlEvents`, `initViews`, `renderMatcherFields(state.curMatcherType)`, `renderActionFields(state.curActionType)`, `updateFormMode()`, `refreshStats()`, `initTopToolsSort()`, `refreshRules()`, `connectWS()`, `syncConnectivity()`, `startEventsPolling()`, then `setInterval(refreshStats, STATS_POLL_MS)`.

## Pages & layout (two-page SPA via hash router)
- Header `.app-header` now has a middle `<nav class="app-nav">` with two `.nav-link`s: **Dashboard** (`href="#/"`) and **Policy Rules** (`href="#/rules"`); active link gets `.is-active`. `#conn-status` unchanged.
- `<main class="app-main">` contains two views: `#view-dashboard.view.is-active` (wraps a `.dash-grid` holding ONLY `#stream-panel`/`#stats-panel`/`#interventions-panel`) and `#view-rules.view` (holds the moved `#rules-panel`). `.view{display:none}` / `.view.is-active{display:block}` — the inactive view stays in the DOM so background flow continues.
- **Live view is BIG:** `#stream-panel{grid-column:span 2; min-height:clamp(460px,62vh,760px); display:flex; flex-direction:column}` with an enlarged `.list-wrap` (fills the panel height, internal scroll). `#stats-panel{span 1}` sits beside it; `#interventions-panel{span 3}` is a full-width row beneath. Mobile ≤960px collapses all to a single column and relaxes the stream min-height.
- The **Policy Rules page** renders `#rules-panel` as a centered standalone card (`#view-rules{max-width:1400px; margin:0 auto; padding:…}`) matching the dash-grid width.

## Data sources (dual-source, self-healing)
- **WebSocket `/ws`** (hand-rolled RFC6455; `transport.connectWS` + keepalive that reconnects after ~3 silent windows) **+ ~2.5s polling** `GET /api/events` fallback, deduped by `eventKey` (`type|sessionKey|at|toolName`, bounded set at `MAX_SEEN_EVENTS`). Guarantees records appear even when the access path can't forward `Upgrade: websocket` (tunnels/port-forwards/webviews) — see `pitfalls.md`. Poll events go through `ingestEvent` only (never refresh WS liveness).
- `GET /api/stats` (~3s poll via `refreshStats`/`renderTopTools`) drives the aggregate tiles + sortable top-tools table.
- A visible **live/polling banner** (`#stream-status`, `setConnected`/`syncConnectivity`) shows the current source instead of a silently-empty list.

## Sections

### LIVE TOOL CALLS (`#stream-panel`)
One row per **logical tool call**, keyed on the event's stable `event.id` (each distinct id → its own row, so batched parallel calls — even same-name, same-turn siblings — do NOT collapse; non-call events append an empty id segment to the dedup key). Columns: status badge (pending → ok/error), tool name, short session key, timestamp, **Duration (ms)**, then **In / Out / Total** (`tokens.input`/`output`/`total`; each renders `—` when absent) and **Size** (the paired result's `chars` — an always-available proxy when a turn reported no usage). A `<th>` header row is rendered above the list in `index.html`: Status | Tool | Session | Time | Duration(ms) | In | Out | Total | Size.
- **Call↔result pairing:** a `tool.result` is matched to its call by `toolCallId === call.id`; with no usable id it falls back to the same NON-EMPTY `sessionKey` + most-recent pending call (a uniform empty key never triggers the fallback). Unmatched results are retained as orphan rows rather than dropped. Both call and orphan rows build their In/Out/Total/Size cells via shared `appendTokenAndSizeCells` (+ `setNumCellText` for in-place updates on result arrival). Rows are updated in place via `updateCallRowWithResult` / `matchAndRenderResult` / `findCallForResult` (created by `createCallRow` / `createOrphanResultRow`).
- **Click-to drill-down:** toggling a row's `.s-expand` reveals an inline `.row-detail` block — full args (pretty-printed JSON), result `ok`/`chars`/`durationMs`, the FULL session key, and `ruleId` + `action` if an intervention fired (`storeInterventionForDrillDown` / `renderRowDetail` / `bindRowClick`). Toggling one row does not collapse the others.
- **Filters:** a `.stream-filters` bar (tool name / status / session) with a "showing X of Y" count, client-side over the buffered rows (`applyFilters` / `bindFilterEvents`), composing with the time range below.
- **Bounded history:** items cap (~200; `trimCallData` / `MAX_LIST_ITEMS`) into a scrollable `.list-wrap`; each retained row carries `data-at` (and `data-session` for interventions) for time filtering/export.
- `ingestEvent()` is the single deduped entry point that renders both WS and poll events.

### COUNTS & TOP TOOLS (`#stats-panel`)
Tiles: total calls/results; avg duration (ms); total/input/output tokens (all `—` until data exists); a live row (this-session / results / interventions); a **sortable top-tools table** (Tool | Calls | Avg(ms) | Max(ms)); footer "Interventions retained".
- **The "total (ms)" tile was REMOVED** (there is no `total-duration` element anywhere under `dashboard/` anymore); only the per-tool **Avg (ms)** and **Max (ms)** remain, plus global avg-duration.
- Absent metric fields render `—` via `fmtOpt()`. The meaning of `—` (**"no data yet"**, not an error) is explained via a native tooltip: a shared `NO_DATA_TIP` constant + `setStatValue()` helper attach a `title` only while a tile shows `—`; `renderTopTools`/`statNumCell` set/clear it on the `Avg(ms)`/`Max(ms)` headers, each empty cell, and add a muted footnote under the table.
- The **Results count** reflects `CollectorSummary.totalResults` (real per-result pairing) — see `tool-metrics.md`. Aggregates (tiles + top-tools) EXCLUDE nested-wrapper tools (default `task`) via `aggregate-exclusions.ts`, so the Top Tools table has no `task` row while the live stream still shows each `task` event.
- **Sortable table (client-side, no deps):** each `<th>` in `#top-tools` thead has a `data-sort` key (`tool`/`calls`/`avg`/`max`) + `<span class="sort-ind">`, an `aria-sort`, and clickable affordance. `stats.mjs` exposes `initTopToolsSort()` (wired once in `init()`), which keeps module-local sort state and re-renders `renderTopTools` output sorted: numeric columns compare numerically, the tool-name column case-insensitively, and rows whose value is absent (`—`) **always sort last** regardless of direction. First click applies the column's natural direction (tool→asc, calls/avg/max→desc); further clicks toggle asc/desc, updating the ▲▼ indicator, `aria-sort`, and the `.active`/`.sorted-col` highlight. Until the user clicks a header, the table keeps the server's original order.

### INTERVENTION LOG (`#interventions-panel`)
Structured rows (`addInterventionRow`): distinct cells **Time (`iv-time`) | Rule id (`iv-rule`) | Action-type badge (`iv-action`, class `badge-interv`) | Detail message (`iv-detail`)**, built from `InterventionEvent {at, ruleId, action, detail?}` with per-cell `title`s (DOM-built → auto-escaped). Empty state = inline SVG pulse icon + text + a hint of what will appear. Same bounded cap as the stream. On the dashboard page this panel spans the full width beneath the stream/stats row.

### POLICY RULES (`#rules-panel`, now its OWN page — `#view-rules`)
A rules list + an authoring form, reached via the "Policy Rules" nav link / `#/rules` hash. Each **rule row** (`renderRuleRow`) exposes an enabled checkbox, description, id, and **Edit / Delete** buttons; clicking Edit loads the spec into the form (`loadSpecIntoForm`). Form flow: `makeField`/`renderMatcherFields`/`renderActionFields` build dynamic matcher/action fields; `collectSpec`/`submitRule`/`saveRule` persist (REST `POST`/`PATCH`); `resetForm` manages add mode; `toggleEnabled`/`deleteRule` mutate the store (REST `PATCH`/`DELETE`). Matcher/action type, Window, Require-consecutive, Param identity, Result identity, Description, Priority, and Enabled all carry help hints/tooltips (Priority: "lower number = higher precedence; blank = default"). Navigating to the page calls `refreshRules()`. See `api-reference.md` for RuleSpec shapes.

## Global controls toolbar
- **Time range** (`filter-time`; presets All / 5m / 15m / 1h + custom from–to via `filter-time-from`/`filter-time-to`): filters both calls and interventions by `at`, composing with the tool/status/session filters (`time.inTimeRange` / `controls.onTimeRangeChange` / `applyCustomTimeRange`).
- **Clear on-screen history** (`btn-clear-history`): wipes only the client-side buffered events + DOM rows + live counters; keeps the dedup `seenEventKeys` set so polled replays don't repopulate; does **NOT** touch server aggregates (there is no server-side wipe endpoint).
- **Export** (calls & interventions, JSON + CSV): native `Blob` + `URL.createObjectURL` + `a.click()`. CSV is RFC-4180 (calls: type/at/time/toolName/sessionKey/status/durationMs/tokensInput/tokensOutput/tokensTotal/sizeChars; interventions add ruleId/action/detail). Helpers: `getVisibleCalls`/`getVisibleInterventions`/`buildCallsCsv`/`buildInterventionsCsv`/`exportJson`/`exportCsv`/`downloadFile`. Wired in `init()` via `controls.bindControlEvents()`.

## Business rules / assumptions
- **Zero-dep vanilla JS, modular ES modules** — no framework, no `ws` package, no bundler/compile; stay consistent (`el()`, existing class naming, `—` for absent values); keep the module graph acyclic and avoid duplicated symbols.
- The stream is a **bounded ring buffer** (~200 items); time-range + export operate over the retained window, not full lifetime history.
- **Per-row duration/tokens** rely on call↔result pairing by id (sessionKey fallback) and inherit the sequential-single-client assumption of the backend metrics (`tool-metrics.md`).
- `—` = "no data yet" (early run), never an error.
- "Clear history", time-range, top-tools sorting, and export are **client-side only**; they do not mutate server state.

## Testing / verification
No DOM/browser tests exist (the e2e suite only asserts the dashboard files are *served*). After any dashboard edit, verify with:
- `node --check` on EVERY `dashboard/js/*.mjs` and on `dashboard/app.js` (app.js parses as ESM; if node flags it as CJS, copy to a temp `.mjs` and re-check).
- `npm test` (baseline ~167 green, no regression) — includes `tests/server-integration.test.ts` assertions that `/js/state.mjs` is served with a JS content-type and that path-traversal requests return non-200.
- A structural check: every `from './X.mjs'` import resolves, the import graph is **acyclic**, no symbol is defined in >1 module, and `app.js` contains only imports + `init()`.
- A DOM-id cross-reference: every STATIC id referenced by the modules (`$('…')`, `getElementById('…')`, `querySelector('#…')`) exists in `index.html`; spot-check panel ids and toolbar/export buttons.
- A runtime HTTP smoke against the built server: all assets (`/`, `/app.js`, `/styles.css`, every `/js/*.mjs`) return 200 with the correct Content-Type (modules → `application/javascript`), and missing/traversal paths → 404.
- A **manual browser smoke-test**: tooltips render, drill-down toggles, filters apply, top-tools columns sort (▲▼), policy-rules page shows/hides via nav, export download fires. See `pitfalls.md`.
