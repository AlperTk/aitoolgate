## 4. Key Findings & Technical Notes
### Environment / how to run
- Project: zero-dep Node.js LiteLLM-style proxy at `/sandbox/mcp-manager`. Hexagonal/ports-and-adapters under `src/`; composition via `createXxx()` in `src/server/index.ts`. **Tests run against compiled `dist/` → `npm run build` BEFORE `npm test`.** Telemetry must be non-throwing (`safeEmit`). Centralized translation in `src/proxy/translate.ts`. Dashboard: dark theme, token-first CSS (`dashboard/css/tokens.css`; import order tokens→base→layout→components→rules→controls→table→responsive; cascade order matters), viewport-fit fixed-height layout ≥961px, natural flow <960px (long content scrolls inside its own container).
- **Config env vars** (from `config/config.ts`): `PORT` (listen, default 8787), `UPSTREAM_BASE_URL`, `UPSTREAM_MODEL`, `UPSTREAM_API_KEY`, `UPSTREAM_PROTOCOL`.
- **Dashboard endpoints:** page `http://localhost:8787/`; API base `/api/` → `/api/stats`, `/api/events` (retained ring buffer, capped ~200), `/api/rules` (CRUD); health `http://localhost:8787/health` → `{"status":"ok"}`; proxy routes `POST /v1/chat/completions` (OpenAI) & `POST /v1/messages` (Anthropic), `GET /v1/models`; WebSocket `ws://localhost:8787/ws` (**NO initial snapshot** — new clients get only live events; BUT the dashboard also polls `/api/stats` + `/api/events` on load, so **load-after-seed populates everything**: Top Tools + stat tiles immediately, stream view with most-recent ≤200 events).
- **Running processes / logs (may need restart):** mock upstream PID 7172 → `.chromium-test/mock-upstream.log`; app PID 7203 → `.chromium-test/app-server.log`. Restart from scratch:

### BROKEN — defects to fix (frontend-only):
1. **Rules list empty-state not hidden when rules exist.** The `.empty.empty-lg` ("No rules yet") stays `display:flex`/visible even with ≥1 `.rule-card`. Must hide when count>0, show when 0 (already correct at 0). Likely in `dashboard/js/rules.mjs` `renderRules`/refresh or `views.mjs` list-view data-driving, plus `dashboard/html/rules-view.html`.
2. **Dashboard toolbar filters do NOT filter displayed rows.** Verified with faithful Playwright interactions: typing `serena_read_file` in the tool-name input (placeholder ~"Tool name…") leaves ALL tools visible; selecting `Pending` in the status `<select>` (options: All statuses/Pending/OK/Error/Intervention/Unmatched result) still shows both `pending` and `ok`. Rows are `main ul li .row-main` (ul = `.stream-list` in `.list-wrap`). Almost certainly the whole filter subsystem is non-functional — **tool-name text**, **status select**, and likely also **session-key text** (~"Session key…") and **time-range select** (All retained/Last 5 min/Last 15 min/Last hour/Custom…). Make ALL of them actually filter the displayed stream client-side over the retained buffer; they should combine (AND), reset cleanly, and ALSO apply to newly-streaming events so the live view stays consistent. Investigate `dashboard/js/live-view.mjs`, `dashboard/js/views.mjs`, `dashboard/js/stats.mjs`, `dashboard/js/dom.mjs`, `dashboard/index.html`.
3. **Export buttons didn't produce a downloadable file.** "Calls · JSON", "Calls · CSV", "Interventions · JSON", "Interventions · CSV" produced no download in a headless capture (test was on an emptied list, so inconclusive — re-test with data). Ensure each exports current (ideally filtered) data into a valid Blob download (`Blob` + anchor `download`) without error, and handles empty gracefully. Locate these buttons in `dashboard/index.html` / `dashboard/js/*`.
